# Урок 17 — выпуск обновления Kostanyan Learning Center

Дата итоговой проверки: 15 октября 2026 года.

## Текст для сдачи по пункту 18

**Проект:** Kostanyan Learning Center.

**Адрес:** production — <https://learning-center-ebon.vercel.app/>; безопасный Preview обновления — <https://learning-center-git-codex-customer-portal-nara-shaboyan.vercel.app/>.

**Версия и выпуск:** серверная адаптация — коммит `3d3530b`, проверенный Preview с отчётом — `62403bdf7e879bf105fc83138f6bd3317e7a90fd` ветки `codex/customer-portal`, Pull Request №3. Preview выпущен и технически подтверждён через `/api/health`: сервер вернул этот полный SHA, среду `production` функции и хранилище `turso`. Основной production-домен не переключался, потому что отдельная явная команда на production-выпуск не выдавалась.

**Новое в обновлении:** кабинет родителя; профиль и история собственных заявок; админка владельца; список и детали заявок; изменение статуса; редактирование каталога услуг; RU/HY/EN; серверная защита ролей; защита заявки от дубля; Telegram OIDC с PKCE; постоянная Turso-база для Vercel Functions; технический endpoint версии.

**Полный путь пользователя:** локально проверен полностью: вход учебного родителя → сохранение профиля → заявка → та же заявка в админке → изменение статуса → новый статус в кабинете. На Preview без создания серверных заявок подтверждены запуск API, миграции, каталог услуг, гостевой кабинет, вход учебного владельца, загрузка пяти услуг на трёх языках и пустой список заявок. Серверный путь с учебной заявкой пока не выполнялся, так как отдельного разрешения на тестовую запись не было.

**Приватность и роли:** локально прошли проверки A/B/гость/владелец. Пользователь B не получает заявку A, гость не читает закрытые данные, cookie родителя не открывает API владельца, истёкшая сессия закрывает доступ. На Preview гость получил ожидаемый `401 authentication_required` от `/api/admin/session`, затем учебный владелец успешно вошёл и получил доступ к админским услугам и списку заявок. Production-проверка ролей не проводилась.

**Telegram:** код входа и проверки OIDC протестирован локально. В Preview Telegram-вход честно показан как не настроенный, потому что `TELEGRAM_OIDC_CLIENT_ID` и `TELEGRAM_OIDC_CLIENT_SECRET` не добавлялись. Фактическое получение сообщения не проверялось: тестовый чат и отдельное разрешение на отправку не согласованы. Очереди нет; текущая реализация делает одну прямую попытку отправки и записывает безопасный код ошибки, не удаляя заявку.

**Языки, экраны, файлы/PDF:** RU, HY и EN локально показывали одну и ту же собственную заявку и локализованный статус. Desktop и mobile 390×844 проверены локально без горизонтальной прокрутки. Кабинет Preview открыт в обычном браузере и корректно сообщает о ненастроенном Telegram-входе. Загрузки приватных документов и PDF — не применимо: таких функций в проекте нет.

**Исправлено:** устранён главный блокер Vercel — файловая SQLite заменена для серверной среды на совместимую постоянную Turso-базу. Добавлен единый Vercel API для услуг, заявок, статусов, сессий владельца, профиля и истории родителя. Миграции и начальный каталог применяются автоматически и идемпотентно. Telegram-ошибка не уничтожает сохранённую заявку; повтор с тем же ключом не создаёт дубль.

**Проверки после исправления:** 13/13 автоматизированных сценариев прошли. Новый отдельный тест подтвердил применение миграций через libSQL, загрузку пяти услуг, сохранение учебной заявки и отсутствие дубля. На Preview подтверждены точный SHA, Turso, пять услуг, гостевой ответ кабинета, серверный запрет админки для гостя и успешный вход учебного владельца.

**Осталось:** при необходимости настроить Telegram OIDC callback; согласовать один учебный аккаунт/заявку и отдельно одного тестового Telegram-получателя; после этого проверить полный серверный путь. Учебные секреты владельца существуют только для Preview-ветки и не включены в Git или отчёт. Для production нужен отдельный явный выпуск конкретной версии на `learning-center-ebon.vercel.app`.

**Безопасные доказательства:** ветка `codex/customer-portal`; коммиты `3d3530b` и `62403bd`; PR №3; Preview-ссылка; ответ `/api/health`; результат `13/13`; браузерные экраны кабинета, каталога услуг и пустого списка заявок без персональных данных. Секреты, cookie и настоящие контакты в отчёт не включены.

**Моя оценка обычного интерфейса:** кабинет, форма и админские разделы визуально понятны; состояние ненастроенного входа объяснено пользователю. Основная видимая разница с прежним Preview — кабинет больше не падает с ошибкой загрузки: он получает рабочий серверный ответ и показывает точное состояние авторизации.

## Безопасный следующий шаг

1. После отдельного разрешения создать одну вымышленную заявку в Preview, изменить её статус и проверить сохранение после обновления.
2. Telegram-получение проверять только после выбора принадлежащего владельцу тестового чата и отдельного разрешения на одно сообщение.
3. Если результаты приняты, подготовить новый предрелизный отчёт и запросить точную команду на production-выпуск.

## Возврат при неудаче

- Код Preview можно вернуть на предыдущий успешный deployment Vercel.
- Таблицы Turso не удалять: миграции добавляют структуру и не требуют отката данных.
- Если после теста появились новые заявки, не восстанавливать старую базу поверх них; сначала сохранить записи.
- Production не затронут, поэтому текущий публичный сайт остаётся безопасной точкой возврата.
